# 01 — تقرير جاهزية التكامل قبل التنفيذ

التاريخ: 2026-11-18. أُعد هذا التقرير **قبل أي تعديل على المصدر أو الإعداد** في Phase05، بعد جرد الملفات وفحص العقود والكود وقراءات HTTP/SQL وإعادة الاختبارات القائمة. طلب المالك الحالي تصريح بتنفيذ Phase05 فقط؛ لا نشر ولا Phase06.

## القرار: جاهز لبدء التحقق — PASS WITH LIMITATIONS
لا توجد مرحلة Backend أو Frontend مفقودة وظيفيًا تستلزم إيقاف العمل. لا نعتمد نجاح التقارير السابقة وحده: أعيد الآن تنفيذ TypeScript للطرفين وESLint للواجهة و48 اختبار backend (33 PostgreSQL + 15 وحدة) و44 اختبار frontend، ونجحت كلها. API3001 يعمل وNext3000 يعيد بيانات عبر HTTP rewrite إلى API3004 الاختباري؛ PostgreSQL17.12 متصل عبر TCP، وmigration الأولى مطبقة. هذا **تقرير دخول** وليس إعلان نجاح Phase05 أو جميع E2E المطلوبة.

## ما فُحص
- جرد المستودع والمصادر والإعدادات والاختبارات وملفات الترحيل والبيئة مع حجب القيم الحساسة.
- متطلبات Phase00، وقواعد BR ومعايير القبول، وتدقيق Phase01 ومخاطره وخطته.
- تصميم Phase02: npm Workspaces، المعاملات وقفل النوع، قيود SQL، DTO والعقد، حدود frontend.
- تقارير التنفيذ والاختبارات في Phase03 وPhase04؛ حالات BLOCKED القديمة في Phase01 تعكس وقتها قبل الاعتمادات والتنفيذ اللاحق، ولا تُعدّل تاريخيًا.
- Fastify app/routes/schemas/services/plugins/errors/env/server، Prisma schema وmigration وseed وtest helpers؛ Next page/layout/client hook/components/api-client/types/rewrite وأدوات الاختبار.
- لا pnpm-workspace.yaml ولا pnpm lock: **npm Workspaces قرار Phase02 المعتمد** وهو الموجود فعليًا. لا تحويل مدير حزم دون داعٍ؛ فحص pnpm يسجل «غير مستخدم» لا عطلًا.

## مسائل ظاهرة قبل التعديل
1. 16 high معلنة في أدوات التطوير من المرحلة السابقة؛ يلزم audit جديد ولا إصلاح قسري أو ادعاء حلها.
2. root build/typecheck/test تخص backend فقط؛ أوامر web منفصلة، وسنضيف أوامر quality واضحة بدل تغيير معناها بصمت.
3. .gitignore يتجاهل `.env.*` ولا يستثني `.env.local.example`؛ سنصحح إدراج أمثلة الواجهة بلا أسرار. لا مجلد .git فعلي، لذلك لا يمكن إثبات خلو تاريخ Git غير المتاح من الأسرار.
4. health يقيس حيوية HTTP وليس جاهزية DB لكل طلب؛ PostgreSQL استجاب عبر TCP بينما `pg_isready` الافتراضي على Unix socket لم يجد خادمًا هناك. ليس ذلك تعطل DB؛ يجب تحديد host صراحة.
5. المعاينة الحالية مرتبطة بقاعدة الاختبار السابقة؛ سنستخدم **قاعدة Phase05 مخصصة منفصلة** للاختبارات المدمرة والفشل والتزامن، دون reset لقاعدة تطوير أو إنتاج.

## خطة التنفيذ ضمن الإذن
إضافة harness تكامل اختباري وتشغيل production محلي، اختبار A–G عبر HTTP والمتصفح مع قراءات DB مستقلة للمصالحة، حقن فشل في قاعدة اختبار فقط، فشل نقل وتعافي، إعادة quality والأدلة والتوثيق. لا تغيير قواعد الأعمال أو schema أو API أو تصميم الواجهة. عند اكتشاف عيب حرج يستدعي تغيير العقد/المعمارية نتوقف لطلب الموافقة. بصمات baseline محفوظة قبل التعديل للمقارنة النهائية.


## تحديث بوابة ملزم بعد محاولة الترحيل النظيف — BLOCKED
أظهر اختبار إعادة الإنشاء الفعلي خطأ P3019 في Prisma7.10.1، ولذلك يسري الآن **BLOCKED** بدل قرار الدخول الأولي أعلاه. التقرير الأولي كان مبنيًا على الكود والقواعد الموجودة والاختبارات الناجحة، ولم يكن قد أثبت replay جديدًا. قاعدة `team_equipment_phase05_test` أنشئت منفصلة، لكن `prisma migrate deploy` فشل قبل إنشاء الجداول.

السطر الموجود: `provider = "postgresql" # تثبيت مزود قاعدة البيانات لتاريخ الترحيلات`. رسالة Prisma تفيد أن المزود في lock قُرئ كـ`postgresql" # ...` بدل `postgresql`. الملف يسمح بتعليقات TOML لغويًا، لكن قارئ هذه الأداة لا يقبل التعليق الطرفي هنا. **لم يُعدّل الملف** ولم نحذف تاريخ الترحيل أو ننفذ اقتراح Prisma بالبدء بتاريخ جديد.

التصحيح المقترح يحتاج موافقة الاستئناف بعد شرط الإيقاف: تعليق عربي مستقل قبل `provider = "postgresql"`، واستثناء هذا السطر الحساس من شرط التعليق الطرفي مع توثيقه. لا تغيير schema/migration.sql/API أو قواعد. بعد الموافقة يجب إعادة الترحيل النظيف ثم جميع الفحوص؛ لا إعلان اكتمال Phase03 أو Phase05 حاليًا اعتمادًا على القواعد القديمة.
