# 05 — تدقيق Prisma وPostgreSQL

## الموجود والمفقود
Prisma Schema وprovider configuration وconnection configuration وmodels وmigrations وconstraints وrelations وindexes وseed configuration: **Missing** في المستودع. Transaction support للاتصال الفعلي: **Not Verified**؛ لا قاعدة محددة أو عميل متاح، ولا اتصال محلي مقبول على 5432. لا استعلامات أو migrations أو introspection أو seed شُغلت.

## ملاءمة النموذج المفاهيمي السابق
| الكيان | المفهوم في Phase 00 | فجوة التنفيذ |
|---|---|---|
| Employee | هوية واسم؛ موظفون مُدخلون مسبقًا | لا model أو seed |
| Equipment | نوع معدات وهوية واسم وحساب مخزون | حفظ total/available أو الاشتقاق لم يُحسم |
| Loan | مرجع موظف ونوع ووقت استعارة وإكمال اختياري | لا model أو قيود |

العلاقات Employee 1:N Loan وEquipment 1:N Loan موثقة مفاهيميًا فقط. النوع ليس وحدة برقم تسلسلي. يذكر الطلب الحالي إجماليًا ومتاحًا؛ يجب في Phase 02 حسم تمثيلهما دون تغيير متطلبات العرض والاتساق.

## فحوص التصميم المطلوب تأجيل حسمه
- الفرادة تخص القرض النشط للموظف والنوع لا كل التاريخ؛ unique عام سيمنع إعادة الاستعارة خطأً.
- الإرجاع يكمل السجل ولا يحذفه، والدورة التالية تنشئ سجلًا جديدًا.
- المخزون غير سالب، ومع إجمالي ثابت: المتاح + النشط = الإجمالي.
- تكرار الإرجاع لا يغير الرصيد أو معلومات إكماله مرة ثانية.
- فحوص الأهلية وتغيير المخزون والسجل في معاملة محمية من التزامن، لا check-then-write غير محمي.

Phase 00 تقترح قفل صف المعدات قبل إعادة الفحص والكتابتين، مع دراسة حارس فرادة للنشط. هذا خيار للتحليل وليس قرارًا مثبتًا؛ يلزم تقييم Prisma والإصدار واحتياج SQL محدود وترتيب الأقفال وrollback والتعارضات في Phase 02 بعد فك البوابة. لا SQL أو Prisma schema في هذا التسليم. المحاكاة وحدها لا تثبت صحة حماية قاعدة البيانات.
