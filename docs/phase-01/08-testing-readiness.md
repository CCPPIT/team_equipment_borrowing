## استراتيجية مشروطة للمرحلة التالية
- Unit Tests: التحقق والمنطق الصرف وتحويل أخطاء العمل، دون ادعاء إثبات locking بالمحاكاة.
- Integration Tests: خدمات Prisma ومعاملات PostgreSQL حقيقية، وفحص السجلات بعد commit/rollback.
- API Tests: الطلبات السليمة والمشوهة والموارد المفقودة وعدم تطابق الموظف وحالات HTTP وشكل الأخطاء. يمكن تقييم Fastify inject دون اختيار أدوات إضافية الآن.
- Frontend checks: التحميل والفراغ والخطأ والانتظار ومنع تكرار الإرسال وتبديل الموظف والنجاح وفشل التحديث اللاحق.
- Database Test Strategy: قاعدة اختبار منفصلة عن بيانات الاستخدام؛ لا تنظيف مدمر دون تحقق صريح من هدف الاتصال. إعداد وتهيئة وتنظيف محدد ومتكرر، مع منع التداخل بين fixtures الاختبارات.
- Test Data/Seed: موظفان على الأقل ونوعان مع أرصدة تغطي الصفر وآخر وحدة والمخزون الكافي؛ هذه بيانات اختبار مقترحة لا اعتماد لبيانات عرض نهائية. لا seed منفذ.

تزامن TEST-06 يغطي الزوج نفسه، وموظفين على آخر وحدة، وإرجاعين للسجل نفسه، وتداخل Borrow/Return. تُقبل النتائج المتسلسلة الصحيحة دون اشتراط هوية الفائز. يلزم تسجيل الأوامر والمخرجات والبيانات النهائية لاحقًا. Vitest مرشح للتقييم وليس حزمة ثبت وجودها أو قرار تثبيت الآن. لا منصة ضغط أو CI ضمن النطاق.
