# 10 — مسودة خطة التنفيذ المشروطة

**هذه قائمة تسلسل ومخرجات للتحقق بعد فك البوابة، وليست تصميمًا نهائيًا أو بدءًا لأي مرحلة.** اعتماد Phase 00 ما زال Not Verified. لا نختار إصدارات أو package manager أو schema أو routes نهائية هنا.

| المرحلة | المسؤولية الهندسية | الأعمال بعد الموافقة | المخرجات المتوقعة | معيار الخروج والدليل |
|---|---|---|---|---|
| Phase 02 — System Architecture & Technical Design | Architect وDB وAPI | حسم البنية والنموذج والعلاقات والقيود وحساب المخزون وAPI Contract والمعاملات والأخطاء وهيكل المجلدات وتوافق الإصدارات | وثائق تصميم وقرارات قابلة للشرح دون خدمات زائدة | اعتماد واضح؛ تغطية الفرادة النشطة وآخر وحدة وتكرار الإرجاع وrollback؛ لا تنفيذ تلقائي |
| Phase 03 — Backend Engineering | Backend وDB وQA | إعداد Fastify وPrisma وPostgreSQL؛ models/migrations/seed؛ Equipment/Borrow/Return وقراءة موظفين داعمة؛ validation والأخطاء والقواعد والمعاملات واختبارات backend | API وDB واختبارات وفق التصميم المعتمد | تشغيل PostgreSQL فعلي واختبارات الست وحالات الموارد والمدخلات؛ حفظ التاريخ؛ توثيق النتائج |
| Phase 04 — Frontend Engineering | Frontend وQA | Next.js ومحدد الموظف وقائمة المعدات وBorrow/Return؛ loading/error/empty/pending؛ الربط بالـAPI والنجاح والفشل | واجهة بسيطة مرتبطة بخلفية حقيقية | تدفق دون reload كامل؛ منع النقر المكرر؛ سلامة تبديل الموظف والردود القديمة؛ لا مكتبة حالة غير لازمة |
| Phase 05 — System Integration | Full Stack وQA | تحقق تدفق الاستعارة والإرجاع وإعادة الاستعارة وتحديث المخزون واتساق الواجهة | نتائج تكامل قابلة للتكرار | تحقق employee switch وconflict ونجاح العملية مع فشل refresh؛ لا بيانات وهمية بديلة |
| Phase 06 — Quality Assurance | QA ومراجع تقني | تنفيذ الاختبارات المطلوبة وقواعد العمل والفشل والتزامن؛ مراجعة جودة TypeScript والتعليقات؛ typecheck وbuild | سجل أوامر ونتائج ومشكلات وإصلاحات ضمن تفويض المرحلة | لا إعلان نجاح بلا تشغيل؛ تغطية invariants والتاريخ والبيانات النهائية |
| Phase 07 — Documentation & Delivery | الفريق والمالك | README ومتطلبات التشغيل وأوامر التثبيت وتجهيز DB والاختبارات وAPI والقرارات والقيود؛ ZIP أو رابط مستودع | حزمة تسليم قابلة للمراجعة وتشغيل محلي موثق | تجربة إعداد نظيف موثقة وتسليم دون أسرار؛ لا production/CI |

## ترتيب الاعتماد
بوابة أولى: اعتماد Phase 00 وتسوية مطابقة المعرّفات. بوابة ثانية: مراجعة نتائج تدقيق Phase 01 والإذن بـPhase 02. اعتماد التصميم يسبق برمجة Phase 03. كل انتقال يحتاج موافقة صريحة حسب تعليمات المالك؛ لا تصريح مسبق بالمراحل من وجود هذا الجدول.

## تبعيات تحتاج قرارًا لا تثبيتًا الآن
اختيار مدير الحزم وإصدارات متوافقة، وطريقة توفير PostgreSQL محليًا مع إمكانية Docker إذا توفرت واعتمدت دون فرضه، وبيانات العرض، واختيار الموظف الابتدائي، وعقد الأخطاء والإرجاع السابق، وحدود التعليق العربي لكل سطر. packages/ مشتركة غير لازمة افتراضيًا.

## حدود التنفيذ اللاحق
تعليقات عربية للأسطر التي تقبل التعليق بعد توضيح الاستثناءات؛ لا JSON غير صالح. لا مصادقة أو إدارة موظفين أو إنشاء معدات أو إدارة مخزون أو serials أو due dates أو fines أو reservations أو notifications أو workers أو queues أو distributed systems أو stress infrastructure أو deployment أو CI أو styling معقد أو custom monorepo tooling أو shared UI library غير لازمة.

لا تقديرات زمن أو أهداف أداء مخترعة، ولا ملف إعداد أو كود أو migration أو dependency أُنشئ لتطبيق هذه الخطة.
