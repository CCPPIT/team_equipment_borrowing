# 07 — جاهزية API

الحالة: **Partially Verified على مستوى التوثيق فقط؛ Missing للتنفيذ**. وثيقة Phase 00 رقم 07 تتضمن مقترحًا؛ لا API Contract نهائي أو خادم أو route أو تحقق أو response schema تنفيذي.

| العملية | Method المطلوب | المدخلات المفاهيمية | الاستجابة المطلوبة | الحالة الحالية |
|---|---|---|---|---|
| عرض المعدات | GET | employeeId | هوية واسم النوع والمتاح وحالة الموظف ومعرّف استعارة نشطة أو غيابها | موثقة فقط |
| Borrow | POST | employeeId وequipmentId | سجل نشط جديد لوحدة واحدة بعد commit | موثقة فقط |
| Return | POST | employeeId وloanId | إكمال السجل مرة واحدة بعد commit | موثقة فقط |
| قائمة الموظفين الداعمة | GET | لا شيء | معرّفات وأسماء الموظفين المُدخلين مسبقًا | ضرورية للمحدد وليست إدارة موظفين |

## تدقيق عناصر العقد
Methods والأغراض والمدخلات وردود مفاهيمية والتحقق وأخطاء العمل وفئات HTTP موجودة في المقترح. المسارات النهائية وبنية الحقول الدقيقة والتواريخ وصيغة المعرفات ورسائل وأكواد الأخطاء تحتاج اعتمادًا. المقترح السابق يستخدم 200 للقراءة والإرجاع و201 للاستعارة، و400 للمدخلات و404 للموارد/عدم مطابقة الموظف و409 للنفاد والتكرار و500 للفشل الداخلي. لا تُثبت هذه الخيارات هنا.

شكل خطأ يتضمن code وmessage مقترح موثق، لكن الاتساق الفعلي Not Verified. يلزم التمييز بين validation errors وbusiness conflicts وأخطاء التخزين. عدم وجود موظف لا يعامل كحالة شخصية فارغة. لا تضف quantity متعددة الوحدات. يجب توضيح سياسة الخصائص غير المعروفة والإرجاع السابق في العقد، لا افتراضها حقائق أصلية.

## شروط الاستعداد اللاحقة
توثيق API Contract ثم اختبارات العقد، فحص كل الموارد خلفيًا، مطابقة السجل للموظف، النجاح بعد commit فقط، أخطاء بلا أسرار، وقراءة متسقة. عرض المخزون ليس حجزًا. إعادة جلب البيانات بعد النجاح كافية، مع تمييز فشل الجلب عن فشل العملية. لا endpoint نهائي مفروض ولا اختبار HTTP منفذ.
