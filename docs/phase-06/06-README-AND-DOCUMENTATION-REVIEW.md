# 06 — مراجعة README والتوثيق
أُعيد تنظيم README كمدخل واحد للمراجع بدل تراكم ملاحظات مراحل قديمة. وثائق Phase00–05 بقيت ببصماتها؛ لا إعادة كتابة للتاريخ بنتائج اليوم.

يغطي README المنتج والمقدرات والاستبعادات، والتقنيات والبنية، وNode وnpm وPostgreSQL، والتثبيت بـnpm ci، وفصل env الويب عن DB، وإعداد PostgreSQL المحلي أو الموجود، وgenerate/migrate/seed، وتشغيل الطرفين في طرفيتين، والبناء الإنتاجي والاختبارات والـAPI والقرارات والقيود وروابط التفسير وشفافية AI.

الأمثلة JSON صالحة، وUUID بيانات seed تطابق المصدر. id الاستعارة وأوقاتها توضيحية ويجب استعمال القيم المعادة فعليًا. لا endpoints أو CRUD أو auth أو quantity مخترعة. اختُبرت روابط README المحلية وأمثلة JSON آليًا.

## مدير الحزم والهيكل
التصميم المعتمد يستخدم npm Workspaces وpackage-lock.json؛ لذلك يوثق README npm10.8.2 وعدم استخدام pnpm، ولا يضيف pnpm lock مزيفًا. اسم ومجلدات المستودع الحقيقية محفوظة. وُحد engines الجذري مع متطلبات web الأشد، ووثق packageManager النسخة المستخدمة.

## دقة الإعداد
شُغلت الأوامر الفعلية، ثم نُسخت المصادر دون node_modules/build/env إلى مساحة نظيفة. أُنشئت env محلية من المثالين داخل النسخة، مع قاعدة PostgreSQL جديدة مستقلة. نجحت فيها: npm ci،generate،migrate،seed،typecheck:all،lint:all،build:all. السجلات clean-stage-1 إلى7 وclean-stage-results.json؛ هذا يثبت تثبيتًا وبناءً نظيفين، لا أننا أعدنا جميع118 حالة داخل النسخة النظيفة.

أوامر تطوير المستودع الكامل هي تشغيل API والواجهة في طرفيتين، وقد اختُبرا فعليًا بمنافذ بديلة. لا مكتبة تشغيل متوازٍ إضافية. دعم الأنظمة ليس شاملًا؛ helper المحلي يعتمد Bash وPostgreSQL native، وtrust محلي معزول فقط.

التوثيق والتعليقات بالعربية. JSON وlock/generated تبقى صالحة دون تعليقات داخلية، وسطر provider في migration_lock يستخدم تعليقًا سابقًا بموافقة Phase05 لأن التعليق الطرفي كسر قارئ Prisma. كل ادعاء اختبار له سجل فعلي؛ لا تنسب الوثائق اختبارات بشرية أو خارجية غير منفذة.
