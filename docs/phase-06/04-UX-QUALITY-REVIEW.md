# 04 — مراجعة تجربة الموظف والوصول
شُغل Chromium على بناء Next الإنتاجي مع Fastify وPostgreSQL حقيقيين. اختُبرت الأرصدة والنشط بعد العمليات، وقُرئت صور320 وkeyboard-focus بصريًا: البطاقات تتكدس دون قطع، والأسماء والأزرار والحالات ظاهرة. لم تُجرَ إعادة تصميم أو إضافة زخرفة.

| المجال | النتيجة الفعلية |
|---|---|
| اختيار الموظف | PASS: قائمة API واضحة، دون اختيار افتراضي أو mutation بلا موظف |
| الفراغ والفشل | PASS: اختبارات المكونات والشاشة وH08 ببيانات DB فارغة فعلًا |
| المخزون والنشط | PASS: أرقام ونصوص واضحة، والنشط يخص الموظف المختار فقط |
| Borrow/Return/Reborrow | PASS: pending ورسائل عربية وتحديث دون document reload إضافي |
| منع التكرار | PASS: قفل ref متزامن وتعطيل المحدد والإجراءات حتى mutation+GET |
| غموض الشبكة | PASS: GET للمصالحة بلا POST تلقائي ثانٍ أو ادعاء rollback |
| لوحة المفاتيح | PASS: Tab لرابط تجاوز المحتوى، Enter، اختيار بالأسهم، Tab للزر، ثمEnter/Space للدورة الكاملة |
| التركيز | PASS بعد إصلاح عيب مثبت؛ V06 يثبت الاستعادة وعدم سرقته من عنصر آخر |
| التجاوب والوصول الآلي | PASS: RTL وعدم overflow وaxe للقواعد المختارة عند320/360/768/1440 |

## العيب والإصلاح
أول تشغيل للمتصفح أعاد5 PASS و1 FAIL في Q01: الزر يفقد التركيز بسبب disabled أثناء العملية. لم نضعف assertion أو نستخدم focus مصطنعًا لتجاوز المشكلة؛ أُصلح EquipmentCard ليستعيد التركيز بعد انتهاء العملية والمصالحة، وفقط إذا لم يختر المستخدم عنصرًا آخر. أُضيف V06، ثم نجحت45 حالة frontend و6 حالات browser، وأعيدت19 system بعد بناء جديد.

اللقطة keyboard-focus تظهر حلقة التركيز على زر الإرجاع، والاختبار أكّد ذلك عبر DOM. صور full-page قد تغير موضع تصوير عناصر fixed خارج viewport؛ حكم التركيز لا يعتمد على الصورة وحدها.

## الحدود
هذه ليست شهادة وصول شاملة. لا قارئ شاشة بشري أو أجهزة فعلية أو Firefox/WebKit أو اختبار تكبير شامل متعدد المتصفحات. بعض النصوص المساعدة صغيرة نسبيًا على الهاتف، ولم تُنفذ دراسة مستخدمين أو benchmark أداء. لا ندعي تحسنًا مقاسًا في re-renders؛ لم تبرر القائمة الصغيرة إضافة memoization أو مكتبة حالة.
