## التثبيت النظيف: ما تحقق وما لم يتحقق
نُسخت المصادر بلا node_modules/.next/build/env إلى مساحة تحقق جديدة. أُنشئت env من المثالين، مع قاعدة `team_equipment_submission_test` جديدة مستقلة. نجحت أوامر npm ci،prisma:generate،db:migrate،db:seed،typecheck:all،lint:all،build:all.

أعيدت مقارنة61 ملف مصدر/إعداد، وpackage.json وpackage-lock، مع النسخة النهائية فكانت متطابقة. تعديلات الوثائق اللاحقة لا تغير الكود المتحقق منه. **لم نعد تشغيل118 حالة داخل النسخة النظيفة**؛ نتائجها من بيئة QA الأصلية بعد الإصلاح. هذا فصل مقصود بين دليل قابلية التثبيت ودليل السلوك.

## سياسة الحزمة الفعلية
تضم apps/api وapps/web وscripts وtests/system وdocs/phase-00…06، وREADME وpackage.json وpackage-lock.json و.gitignore و.env.example ومثال web، وschema وSQL migrations وseed والاختبارات وإعداداتها.

تستبعد node_modules و.next وbuild/dist وcoverage وtest-results وplaywright-report والكاش وملفات .env المحلية وملفات اعتماد/مفاتيح خاصة وقواعد PostgreSQL الثنائية. تُضم أدلة منتقاة في docs رغم تجاهل السجلات التشغيلية العامة في Git. لا pnpm files مزيفة أو تغيير لاسم وبنية المستودع الحقيقيين.

أُزيل فقط مسار test-results قديم مولد تحت tests/system بعد التأكد من غرضه؛ لم يُحذف ملف مجهول الغرض أو dependency غير مثبت عدم الحاجة إليه. ظهرت @img/sharp-wasm32 محليًا كـextraneous حتى بعد npm ci؛ لم تُحذف عشوائيًا لارتباط بيئة الصور/Next المحتمل. node_modules كلها خارج الحزمة، ولا manifest اعتماد جديد لها.

لا يمكن وضع hash للأرشيف داخل الأرشيف نفسه دون دورية. لذلك يسجل evidence/package-manifest.json hashes الملفات (باستثناء نفسه)، ويُرفق خارج ZIP ملف SHA256 ونتيجة verification حقيقية بعد إنشائها. التقرير10 يسجل الموقع والنتيجة، لا رابطًا مختلقًا. إذا فشل أي تحقق من CRC/manifest/required files/secret exclusions لا تُعرض الحزمة كتسليم صالح.

**القرار:** صالح لتقييم الشركة محليًا مع القيود المعلنة، وليس تصريحًا بالنشر العام أو الإرسال الفعلي نيابة عن المالك.
